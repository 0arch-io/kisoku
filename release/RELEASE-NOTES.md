# Kisoku 1.6B release notes (draft, 2026-10-07)

For the GitHub release, the Hugging Face collection description and the launch post. Numbers come from `report/kisoku-report-draft.md`; change them there first.

## One paragraph

Kisoku 1.6B is a base language model pretrained from scratch by one person on a TPU v4-32 from Google's TPU Research Cloud, on about 0.5 trillion tokens, with a single RTX 4090 for evaluation. On a 10-benchmark suite run through the same harness for every model it matches Meta's Llama 3.2 1B (five wins each) while using about 18 times less training data. It was extended to 64K tokens of context and reaches about 128K with YaRN at inference, where it is ahead of Llama 3.2 1B at most lengths but behind IBM Granite 4.0 1B and Qwen3.5. A chat fine-tune ships as a preview. Weights, intermediate checkpoints, GGUF builds, training and evaluation code, the contamination audit and data manifests are all released. The technical report tells the whole story, including what went wrong.

## What is in the release

- `0arch-io/kisoku-1.6b`: final base weights (bf16 safetensors, YaRN x2 default config, plain config beside it). Branches: stage 1, stage 3, long-context Phase A and Phase B checkpoints.
- `0arch-io/kisoku-1.6b-chat`: chat preview, pass 9. Earlier passes as branches.
- `0arch-io/kisoku-1.6b-gguf`: base and chat, F16, Q8_0 and Q4_K_M, for llama.cpp and Ollama.
- `0arch-io/kisoku-1.6b-eval` (dataset): raw per-sample harness results for every model in the tables.
- `github.com/0arch-io/kisoku`: MaxText configs and stage scripts, evaluation scripts, contamination audit, synthetic long-context task generator, data manifests, the report.

Five wins each. Kisoku's wins are reasoning and math; Llama's are knowledge and commonsense, where its 9T tokens show. Qwen2.5 1.5B and SmolLM2 1.7B are ahead of both on most tests.

RULER long context (13-task mean, YaRN x2): 76.1 at 4K, 58.8 at 32K, 56.7 at 64K, 43.2 at 128K. Llama 3.2 1B: 73.5, 56.7, 49.2, 43.1. Granite 4.0 1B and the Qwen3.5 models are ahead at every length.

## What to say plainly

- This is a token-efficiency result on one suite, not a claim that Kisoku is the best small model.
- No distillation was used, but a large share of the pretraining text was rewritten or generated by other language models (Nemotron-CC and similar sets). The report says exactly which.
- Verbatim test-set overlap exists in the pretraining corpus. Accuracy on the clean subset is the same or higher, so it does not explain the scores. The audit and its code are released.
- Long-context scores are partly format familiarity: the Phase C training mix has 18% synthetic tasks that resemble RULER. A held-out long-context suite was not run.
- Without YaRN the model collapses at 128K (4.7 on RULER). Keep the shipped `rope_scaling`.
- Do not set a repetition penalty. It hurt every generation score in testing.

## Chat preview: known limits

The chat model is released so the fine-tuning work in the report can be checked, not as a finished assistant.

- About half of its turns in a long conversation are unacceptable to a strict judge (48.9% acceptable on 297 held-out scripts; Llama 3.2 1B Instruct gets 56.7% on the same test). It loses track of what it said earlier or builds on its own mistake.
- A typo in a longer request can lose the request.
- It refuses some requests it could simply take, and sometimes talks defensively about itself.
- It states wrong answers as confidently as right ones, and declines only some of the questions it gets wrong.
- It occasionally makes unneeded tool calls.
- Safety, bias and multilingual behaviour were not evaluated. Do not deploy it to users.
